# State model

The active pointer is small and records lifecycle stage, stage status, next gate, authorization, and context path. Detailed mutable state stays with the active change. Historical evidence remains in progress and Git. Project documents describe durable facts and domain language. `project/TARGET_STATE.md` and `project/CAPABILITY_MODEL.md` define the accepted completed-state direction. `assessments/current/CURRENT_CAPABILITY_ASSESSMENT.md` is an evidence snapshot of current Coverage/EvidenceConfidence, and `project/GAP_MAP.md` holds accepted causal missing conditions. Current implementation status must not be folded into the Target or Capability Model. Recommendations describe future opportunities and may preserve stable semantic-unit residue. `assessments/current/DIRECTION_HISTORY_RECONCILIATION.md` records the accepted/current snapshot of how recommendation units and historical Roadmap meaning map to the current Project Spine; it does not define priority. Decisions preserve rationale. Optional skill-usage logs are observational only.

See `.planning/control/CHANGE_LIFECYCLE.md` for transitions and `.planning/control/STATE_OWNERSHIP.md` for the normative ownership table.
