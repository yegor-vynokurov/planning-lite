## Explicit compilation boundary

Explicit context compilation is a deliberate, derived 09-F projection that
selects, orders, normalizes, or materializes task-specific context to remove
reconstruction work or bind a material semantic, safety, authority, decision,
terminology, or ordering requirement.

Ordinary use of existing PL06/PL07 references and ordinary AgentWorkPacket
assembly is not automatically compilation. If no selected, ordered, or
normalized context projection is added, explicit compilation did not occur.

## PATH_A: no explicit compilation

When existing accepted PL06/PL07 context and bindings provide unambiguous and
sufficient execution inputs, 09-F uses the existing path directly. No explicit
09-F compiled-context component is produced and no ceremonial empty object is
required.

Existing operation-guidance, work-unit, executor, candidate/baseline,
acceptance/evidence, and PL07 guard identities remain available through their
existing ownership paths and are sufficient for provenance, audit, replay, and
Attempt evaluation where no distinct compiled projection exists.

The AgentWorkPacket may be assembled without an explicit `context` component.
Its production schema is not frozen here.

## PATH_B: bounded compiled context

When a task-material reason exists, 09-F may produce one bounded context
projection. The projection is:

```text
DERIVED
BOUNDED
SOURCE-BOUND
NONAUTHORITATIVE
TASK-MATERIAL
```

Conditional content may include:

```text
context-binding identity
decision-boundary projection
ordered/bounded context references
additional task-specific guard projections
conditional term bindings
```

No element is implied to be always present. A distinct compiled projection
must be bindable to accepted source and input identities. The representation of
that identity, field names, serialization, and object classes are not frozen.

The AgentWorkPacket may carry one optional bounded compiled-context component.
No always-present empty context carrier is required.

## Applicability boundary

Applicability is a cheap, deterministic predicate/decision-table decision
derived only from information already available after:

```text
OperationGuidanceV1
accepted work unit
accepted 09-E capability/executor requirements
already-available ResumeContextV1 metadata
already-known context/source-role metadata
already-known authority/scope/evidence/guard metadata
```

It performs no repository discovery, history discovery, authority re-read,
semantic source search, or extra context-selection stage merely to decide
whether compilation is needed. No uncalibrated weighted scalar, opaque score,
or learned applicability router is part of this architecture.

The conceptual reason families are:

```text
SEMANTIC NEED
SAFETY / AUTHORITY NEED
RECOVERY NEED
ORDERING NEED
```

Terminology ambiguity is a conditional semantic selector, not a separate
production path. Exact predicate names, decision-table rows, reason-code
constants, and thresholds remain unfrozen.

## Recovery and evidence necessity

```text
Most or all eligible evidence required for correctness
-> low or no eliminable recovery opportunity.

A material eligible subset is optional, reconstructive, selectable, or
order-sensitive
-> potential recovery opportunity.
```

Recovery claims concern avoidable discovery, reconstruction, and selection
work. Compilation cannot claim to eliminate evidence that correctness actually
requires inspecting. No numeric or percentage threshold is frozen.

Recovery opportunity is not the only reason for PATH_B. A material semantic,
safety/authority, or ordering projection may select PATH_B even when recovery
opportunity is zero.

`DEFAULT OMIT` is one bounded applicability decision: do not emit an explicit
compiled element unless it has task-material value for semantic interpretation,
authority/control, safety, decision boundaries, ordering, terminology, or
supported recovery. Do not create a recursive discovery decision for each
field.

## Uncertainty and fail-closed behavior

```text
RECOVERY-ONLY UNCERTAINTY:
PATH_A; continue safely when semantic, authority, and safety inputs are already
sufficient.

KNOWN MATERIAL SEMANTIC OR SAFETY NEED
+ resolvable from accepted eligible inputs:
PATH_B.

MATERIAL SEMANTIC / SAFETY / AUTHORITY NEED
that is missing, stale, conflicting, unavailable, or cannot be legally bound:
NON-EXECUTING STOP.
```

Missing provider telemetry or optional recovery evidence is not a blocker for
otherwise safe execution. Existing PL07 guards remain authoritative and
mandatory on both paths; context compilation does not own, replace, or become
a prerequisite for PL07 safety.
